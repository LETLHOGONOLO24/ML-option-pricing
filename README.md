# Machine Learning for European Option Pricing

A Python machine-learning experiment using Random Forest regression to approximate European call option prices generated by the Black–Scholes model.

## Overview

This project explores how supervised machine learning can approximate the relationship between financial market parameters and European option prices.

The experiment uses synthetic data generated from the Black–Scholes pricing framework to train a Random Forest regression model. The model learns to estimate option prices from inputs such as the underlying asset price, strike price, time to maturity, risk-free interest rate, and volatility.

The project forms part of my Honours research in Applied Mathematics, which investigates numerical methods and machine learning for option pricing.

**Main question:** How accurately can a Random Forest model approximate Black–Scholes European call option prices on previously unseen data?

## Objectives

- Generate a synthetic dataset of European call option prices.
- Implement a Random Forest regression model using scikit-learn.
- Evaluate prediction accuracy on a held-out test set.
- Analyse prediction errors using quantitative metrics and visualisations.
- Explore the potential and limitations of machine learning as an approximation tool in quantitative finance.

## Methodology

### 1. Data generation

A synthetic dataset containing 20,000 observations was generated using the Black–Scholes framework for European call options.

The input variables are:

| Feature | Description |
|---|---|
| `S` | Underlying asset price |
| `K` | Option strike price |
| `T` | Time to maturity |
| `r` | Risk-free interest rate |
| `sigma` | Volatility |

The target variable is the corresponding European call option price calculated using the Black–Scholes formula.

The experiment uses the following parameter ranges:

| Parameter | Range |
|---|---|
| Underlying price (`S`) | 50–150 |
| Strike price (`K`) | 50–150 |
| Time to maturity (`T`) | 0.05–2 years |
| Risk-free rate (`r`) | 0.01–0.10 |
| Volatility (`sigma`) | 0.10–0.60 |

These ranges define the synthetic experiment and should not be interpreted as a sample of observed market prices.

### 2. Model training

A `RandomForestRegressor` from scikit-learn was trained to approximate the mapping from the five input variables to the Black–Scholes call price.

The dataset was split into training and test sets:

- Training observations: 16,000 (80%)
- Test observations: 4,000 (20%)
- Random seed: 42

The model configuration was:

```python
RandomForestRegressor(
    n_estimators=150,
    max_depth=18,
    min_samples_leaf=2,
    random_state=42
)
```

The test set was held out during model fitting and used to evaluate the model's predictions.

### 3. Model evaluation

The model was evaluated using three standard regression metrics.

| Metric | Result |
|---|---:|
| Mean Absolute Error (MAE) | 1.0494 |
| Root Mean Squared Error (RMSE) | 1.4934 |
| Coefficient of determination (R²) | 0.9961 |

The model achieved an \(R^2\) of approximately 0.996 on the test set, indicating that its predictions captured much of the variation in the generated option prices.

The MAE of approximately 1.05 represents the average absolute prediction error in the price units used by the dataset. The RMSE penalises larger errors more strongly than the MAE.

These results show that the trained model approximated the synthetic Black–Scholes pricing function well over the sampled parameter ranges. They do not establish that the model is more accurate than the Black–Scholes formula itself.

## Limitations and future work

The experiment uses synthetic prices generated from the Black–Scholes model. Consequently, it tests the model's ability to approximate a known pricing relationship rather than predict real market prices.

The results may also depend on the selected parameter ranges, model configuration, and training data. A high test-set \(R^2\) does not guarantee equally good performance outside the sampled ranges.

Possible extensions include:

- Comparing Random Forest with other regression models.
- Examining errors across different moneyness and maturity ranges.
- Tuning model hyperparameters systematically.
- Testing generalisation on parameter ranges not represented in training.
- Investigating alternative pricing models and, where suitable, market data.
- Comparing computational cost and accuracy under a carefully controlled benchmark.
